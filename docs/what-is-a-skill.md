# Claude Code 技能到底是什么

这份笔记记录我在搭这两个技能时搞清楚的机制，比官方文档直白一些。

---

## 一、技能到底是什么

**一句话：技能不是程序，是一份写给 AI 看的工作说明。**

把它想成"给新同事写的一份操作手册"——你把自己验证过的一套做法写下来，
AI 每次遇到对应的任务，就照着手册做，不用你重新解释一遍。

### 物理上，它就是一个文件夹

```
任意技能名/
└── SKILL.md          ← 必须叫这个名字，必须在这个位置
```

`SKILL.md` 里分成两段：

```markdown
---
name: my-skill
description: 一句话说明这个技能干什么、什么时候该用
---

# 正文标题

具体该怎么做……（想写多长写多长）
```

- 上面 `---` 夹住的那段叫 frontmatter，是给**程序**看的，用来登记和检索
- 下面的正文是给 **AI** 看的，是真正的"说明书内容"

### 一个反直觉的点：命令名来自文件夹，不是 frontmatter

你在对话框里输入的 `/技能名`，取的是**文件夹名**（用了符号链接就是**链接名**），
**不是** frontmatter 里的 `name`。`name` 只是显示用的。

所以：`pptx-animation/` 这个文件夹，对应的就是 `/pptx-animation`。
把文件夹改名，命令名跟着变。

### frontmatter 写坏了会怎样

**不会报错，也不会消失**——技能照样加载，但 **frontmatter 里所有字段全部被丢弃**：
`name` 退回成文件夹名，`description` 退回成正文的第一行。

后果是 AI 再也看不到你那句"什么时候该用我"，**技能实际上就不会被触发了**。
所以出问题时不要去找报错，去检查那三行 `---` 有没有被改坏。

### 除了 description，还有这些字段可用

| 字段 | 作用 |
|---|---|
| `when_to_use` | 专门写"什么时候该用我"，会**追加到 description 后面**。比硬塞进 description 更清晰 |
| `argument-hint` | 用户输入技能名后显示的占位提示 |
| `allowed-tools` | 这个技能生效时允许用哪些工具 |
| `disable-model-invocation` | 设为 true → AI 不能自动触发，只能你手动输入 `/名字`。适合有副作用的操作 |
| `paths` | 只在操作匹配的文件时才加载（条件加载） |

**所有字段都不是必填的**，但 `name` 和 `description` 强烈建议写。

### 它是怎么被触发的

1. 每次会话开始，AI 只会读到所有技能的 `name` 和 `description` 这一行
   （所以你那份 `description` 写得好不好，直接决定它会不会被想起来）
2. 当你的请求命中了某条描述，AI 才会把那个 `SKILL.md` 的**正文**完整读进来
3. 然后照着正文里的步骤去做

这也解释了一件事：**`description` 里必须写清楚"什么时候该用我"**。
只写"处理 PPT"不够，要写"当用户说'加动画''太枯燥了'时使用"——
把用户可能说的原话写进去，命中率才高。

## 二、能不能用 JSON 或 Python 存？

| 方式 | 能不能 | 原因 |
|---|---|---|
| **JSON** | ❌ 不行 | JSON 只能存**结构化数据**（键值对、数组）。技能的正文是"先做什么、再做什么、出错怎么办"这种**流程说明**，是自然语言。JSON 里没地方放这个，也没法让 AI 判断"什么时候该用我"。 |
| **Python** | ⚠️ 只能当零件 | Python **不能替代** `SKILL.md`，但可以放在技能文件夹里当**工具**，让正文去调用它。 |

**正确姿势是两者配合。** 你自己那两条技能就是标准范例：

```
find-literature/
├── SKILL.md        ← 说明书：什么时候用、怎么调脚本、结果怎么解释
└── find_lit.py     ← 工具：真正干活的代码
```

`SKILL.md` 里会写这样的话：

> 运行 `python3 "${CLAUDE_SKILL_DIR}/find_lit.py" "<查询词>"`

`${CLAUDE_SKILL_DIR}` 是自动替换的，指的就是这个技能文件夹本身，
所以脚本放在旁边就能被找到，不用写死绝对路径。

**什么时候该把逻辑放进 Python？**

- 计算、检索、格式转换、批量处理 → 放 Python（确定性的事交给代码）
- 判断、解释、跟用户对话、决定下一步 → 放 `SKILL.md`（需要理解力的事交给 AI）

判断标准很简单：**同一件事每次都要做得一模一样吗？** 是 → 写进 Python。
需要看情况临场决定吗？→ 写进 `SKILL.md`。

## 三、怎么新建一个技能

1. 复制 `templates/SKILL.md`，新建一个文件夹放进去，改个名字（名字用英文小写加连字符，比如 `my-skill`）
2. 打开 `SKILL.md`，填 frontmatter 的 `name` 和 `description`
3. 正文写清楚：核心原则 → 执行步骤 → 必须注意什么
4. 有需要的话，在同级放 Python 脚本，正文里用 `${CLAUDE_SKILL_DIR}` 引用
5. **让它生效**：见下面第四节

## 四、让技能生效

⚠️ **重要：Claude Code 不认识这个仓库里的文件夹。**

它只会在固定的几个位置找技能，最主要的是 `~/.claude/skills/`（个人技能，所有项目都能用）
和 `<某个项目>/.claude/skills/`（只在那个项目里能用）。

所以放在本仓库里的技能，**不建立链接就不会被触发**。
具体怎么关联、怎么排查失效，见 [`installation.md`](installation.md)。
