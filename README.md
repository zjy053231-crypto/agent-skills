# agent-skills

Two small tools that make a large language model do something it is bad at
doing on its own: **cite sources without inventing them**, and **write file
formats it has no API for, without corrupting them**.

Both are packaged as [Claude Code](https://claude.com/claude-code) skills — a
skill being a folder with a `SKILL.md` instruction file that the agent loads
when the task matches. The instruction file is only half of each project; the
interesting part is the script underneath it.

| Skill | Problem it solves |
|---|---|
| [`find-literature`](find-literature/) | Turns a query into GB/T 7714-2015 citations generated from Crossref metadata, not from model memory |
| [`pptx-animation`](pptx-animation/) | Adds click-triggered entrance animations to `.pptx` files, which `python-pptx` cannot do at all |

---

## Why these two

### A model that writes citations will invent them

Ask an LLM for a reference list and it will produce something plausible —
correct-looking authors, a believable journal, a DOI that resolves to nothing.
This is not a prompt problem; it is what happens when text is generated by
predicting likely text.

`find-literature` refuses to let the model write the citation. The model's only
job is to call a script; the script queries the Crossref API and formats the
citation from structured metadata. Anything the metadata does not contain is
omitted rather than guessed.

```
$ python3 find-literature/find_lit.py "prompt engineering creativity" --max 3

[1] Mejía-Trejo J. Artificial Intelligence: Fundamentals of Prompt Engineering
    with ChatGPT as a Creativity-Driving Innovation[EB/OL]. (2024).[2026-11-16].
    https://doi.org/10.2139/ssrn.4950183.

[2] Tümen Akyıldız S. Prompt engineering and creative pedagogical thinking:
    Insights from a qualitative study with teacher candidates[J]. Thinking
    Skills and Creativity, 2026, 60: 102105.

[3] Cotroneo P, Hutson J. Generative AI tools in art education: Exploring prompt
    engineering and iterative processes for enhanced creativity[J]. Metaverse,
    2023, 4(1): 14.
```

Handles the cases that actually break citation formatters: more than three
authors, Chinese names that must not be abbreviated, missing volume or page
numbers, journal articles vs. conference papers vs. monographs vs. chapters in
edited books (`[M]//`), and preprints that need an access date.

### The file format has no API, and writing it by hand corrupts the file

`python-pptx` can build slides but cannot add animations — the object model
simply stops at shapes and text. Animations live in a `<p:timing>` tree inside
each slide's XML, and the tree has deep nesting plus strict element ordering.
Hand-write it from memory and PowerPoint opens the file with *"needs repair"*.

`pptx-animation` takes a different route: **find a real animated `.pptx` on the
machine, use PowerPoint's own output as a structural baseline, generate against
it, then compare node by node.** `anim_check.py` does the comparison, normalising
numeric differences (delays, offsets) so only structural differences are
reported.

The design lesson is the one worth keeping: when a format is under-specified,
do not guess at it — obtain ground truth and verify against it.

## Install

Skills are loaded from `~/.claude/skills/`. Symlink them so edits here take
effect immediately:

```bash
ln -sfn "$PWD/find-literature" ~/.claude/skills/find-literature
ln -sfn "$PWD/pptx-animation" ~/.claude/skills/pptx-animation
```

`find-literature` needs nothing beyond the Python standard library.
`pptx-animation` needs `python-pptx` and `lxml`:

```bash
pip install python-pptx lxml
```

Optional: set `CROSSREF_MAILTO=you@example.com` so Crossref requests join the
"polite pool" and get more reliable responses.

## Usage

**In Claude Code**, the skills trigger from natural language — *"find me
references on prompt authorship"*, *"add animations to this deck"* — or
explicitly:

```
/find-literature 生成式人工智能 创作劳动
/pptx-animation deck.pptx
```

**Standalone**, the scripts run directly:

```bash
python3 find-literature/find_lit.py "generative AI authorship" --max 20 --out /tmp/lit
python3 pptx-animation/anim_check.py check deck.pptx --against
python3 pptx-animation/anim_check.py bank
```

Each `SKILL.md` documents the full workflow, including the failure modes that
cost real time (a dangling `spid`, a missing baseline, a locked file in WPS).

## Testing

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

35 tests, no network required — the Crossref response is never fetched in tests;
`format_gbt7714` is a pure function over a metadata dict, so it is tested
against fixture records covering journal articles, chapters, monographs,
preprints, missing fields and CJK author names.

## Design notes

- **The model orchestrates; the code decides.** Neither skill asks the model to
  produce the artefact. It produces the *call*, and the program produces the
  content.
- **Pure functions at the core.** `format_gbt7714(item, today=None)` takes the
  date as a parameter rather than reading the clock, which is what makes the
  output testable at all.
- **Say what you cannot do.** Both `SKILL.md` files have a section listing known
  limits — Crossref's relevance ranking is mediocre, the animation XML is
  verified structurally but has never been played back on a machine without
  PowerPoint, and so on. A tool that overstates its coverage is worse than a
  narrow one that is honest.

## Limitations

- Crossref metadata is good but not perfect; volume/page errors occur and DOIs
  should be checked before submission.
- `pptx-animation` handles entrance animations only, and structural validity is
  not the same as watched playback.
- Neither tool has been tested on Windows beyond the CI matrix.
